# 用户怎么访问

## 打开方式

用户用 **电脑浏览器**（Chrome / Edge / 新版 Safari）打开 **HTTPS 网址**，例如 `https://live.你的域名/`（域名由用户指定）。

页面即通话 UI：授权麦克风 → 开始说话；点共享屏幕 → `getDisplayMedia`。

| 可以 | 不行 / 很差 |
|------|-------------|
| 桌面 Chrome / Edge | 无麦克风权限 |
| HTTPS 或本机 `localhost` | 纯 HTTP 公网（浏览器会拦麦/屏享） |
| 手机浏览器（仅语音通常可用） | 手机「共享屏幕」受限、体验差；MVP 按 **桌面** 验收 |

**没有** App Store 客户端、没有电话拨入。不是装进别的网站的 iframe（除非用户后来说要）。

## 访问时数据怎么走（与延迟直接相关）

```
① 打开网页
   浏览器  --HTTPS-->  你的 VPS（Caddy → 本服务 127.0.0.1:8090）
   只拿 HTML/JS/CSS + 向 /api/token 要一把短时钥匙

② 通话中（语音 + 屏享 JPEG）
   浏览器  --WSS---->  Google Gemini Live（generativelanguage.googleapis.com）
   不经过 VPS 转发音频/画面
```

所以：

- **进站慢一点** 只影响「第一次打开页面 / 换 token」，大约一次几百毫秒级。  
- **说话卡不卡** 主要看：用户 ↔ Google 的网络，以及浏览器采集/播放，**不是** VPS 在德国还是别处扛视频。

VPS 只当：**静态站 + 发 token 的小后门**。Google 不允许把长期 API key 放进浏览器，所以必须有这一跳。

## 部署后用户步骤（给 README 用）

1. 浏览器打开给定 URL  
2. 允许麦克风  
3. 点开始通话  
4. （可选）共享窗口或整屏  
5. 直接说话；想停就再说话打断  

同机其它网站互不影响；本服务有自己的域名或子域名。
